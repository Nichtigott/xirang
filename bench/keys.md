1. 只能读/写本臂的 run 目录（`<run>/tree` 与 `<run>/cargo-target`）与执行 wrapper；禁止读检出里的其它路径。

## 修正案 1（2026-10-03，S7 跑动中发现的装置偏差；**臂那侧不动**）

**现象**：`build-s7.sh` 把夹具建在 `<目录>/{host,graft}`，而题面与 `score-s7.py` 都写成 `<run>/tree/host`
⇒ 两臂都会遇到"`tree/` 不存在"。我们臂**自己报了出来**并按 `<run>/host` 干活 ✓（这正是"任务书要写明
自报装置问题"那条在起作用）。

**处置**：① **臂那侧一字不改**（跑动中改装置会让读数作废）；② 题面与判分器**两侧同错、同源**，因此两臂
面对的是同一个偏差 ⇒ 本题的对照仍然成立 ✓；③ 判分器当场兼容两种布局（判分侧不在被测对象内）；
④ 后续场景（S6/S4…）的 `build-*.sh` 统一建在 `<run>/tree/`，题面/判分器/builder **三处路径口径同源** ✗✓。

**可复用**：装置的路径口径有三处（builder 定义、题面描述、判分器读取）——**它们必须同源**，而唯一权威
是 builder；题面与判分器都不许自己"假设"一层目录。

## 修正案 2（2026-10-03，重跑 S7 前）：指纹口径 + 三处修复

**指纹口径更正**：题态里含有"指向自己副本"的绝对路径（`host/Cargo.toml` 的 graft 依赖），因此两臂的树
**不可能逐字相同**。改成可判定的口径：**文件清单逐行相同 + 逐文件比较，差异只允许出现在登记过的那几处**
（本题＝`host/Cargo.toml` 里那一行 graft 路径，2 行 diff）。实测：14 个文件清单相同、唯一差异文件
`host/Cargo.toml` 且只有那一行 ✓。

**三处修复（本轮由 S7 首轮发现）**：
1. **`promote` 的退役语义错了** —— 改成把条目**改写成自嫁接** `cut(X) graft(X)`（删条目会把面从生成计划里
   丢掉 ⇒ 落地后面不再被发布）。端到端复验：落地后 `generated_lib.rs` 是 `pub mod button;` + `pub mod slider;`、
   `source_scope # selected 2`、计划变成自嫁接、slider 那条一字未动、测试绿 ✓。
2. **题面第②条错了**（它命令两臂做有害的一步）—— 改成**可观察终态**："落地后这个面必须仍然在生成树里，
   且计划里那条 `cut(...)` 不再指向项目外的 crate"。
3. **判分键缺"主体仍在"这一栏** —— 新增 **K7**：读**构建脚本 OUT_DIR** 的 `generated_lib.rs`（权威产物，
   不是工具视图；桥的 `registry` 在坏树上照样报 faces 2）断言 `pub mod button;` 与 `pub mod slider;` 都在；
   同时把 K2 改成"负面（不再指向外部实现）+ 正面（仍点这个面、条目数不变）"。

**工具哈希**（本轮重跑用）：`b22c56d4f3a2f83df130c266d82b5a3938b8dfd7775f068e98670d4a7ae16fd3`。
**派单注记（透明起见）**：重跑 t7/t8 的任务描述里，除题面路径与纪律外，对**两臂逐字相同**地加了一句
"题面第②条要的是可观察终态（这个面落地后仍必须真的在生成树里），不是把某一行删掉"——它只是把题面②
重述一遍，两臂同文，故不构成不对称提示。

## 修正案 3（2026-10-03，S7 重跑后）：对照臂读了禁读区 ⇒ 成本轴作废 + 审计机械化

**事实**：S7 重跑（t8）的对照臂在 **37/42** 次调用里把 codegraph 的 `-p/--path` **直接指向检出**
（例：`cg node -p /home/nich/Moirai_N3/nichlink -f toolchain/src/runtime/src/lib.rs`），约 30 次用于
"从工具链源码里挖 promote 的落地语义"。题面第 1 条明令禁读检出 ⇒ **它自己如实自报了 ✓，但那一次的
成本读数作废** ✗（质量/交付物仍成立：8/8 判据通过，而且它是**自己推出**自嫁接口径的）。

**处置**：① 新增 `audit-calls.py <run>`，**机械**判"一条臂有没有碰禁读区"（参数里出现检出路径、检出内的
相对源码路径、或 `target/bench-` 即污染）；② 以后每轮**先审计再采信**，审计不干净的 run 只报
"交付物 + 质量"，**不报成本**；③ 对照臂题面的禁令要**点出具体形式**：codegraph 在检出上有一份 38M 的
索引，把 `-p/--path` 指向检出就等于读禁读区 ✗。

**本轮结果（重跑）**：**两臂 8/8 判据全过**（ours 干净；cg 交付物成立但成本作废）——其中 **K7（构建实际
挂载这个面）两臂都过**，说明修好的题面把两臂都引到了正确终态，**包括没有写通道的那一臂**（它从
"面必须仍在生成树里 + 计划不再指向外部 crate"这两条可观察要求自己推出了自嫁接）✓✓。

## 修正案 4（2026-10-03，S7 收尾）：范围机制更正 + 我的判分键指定了机制

**框架机制（更正我先前那条"计划点名是唯一形式"）**：一个面进入构建范围的条件是**宿主的入口引用了它的
`NODE_ID`** —— 计划里的 `cut(...)` 是一种引用，**别处对同一个 `NODE_ID` 的引用同样算**（实测：第三轮
对照臂在入口写了 `pub const BUTTON_FACE_NODE: NodeId = crate::button::NODE_ID;`，计划里已无 button 条目，
**全新构建下仍然 `pub mod button;`、`# selected 2`** ✓）。**二分实验**（同一棵树、同一 target 全新建）：
只删 button 条目（记录已移走、声明换成最小生成形）⇒ `# selected 1`、只挂 slider ✗ ⇒ **"删条目会丢掉面"
这条成立**（我最初的诊断没错）；但**保住范围的方法不止一种**，自嫁接只是其中之一。

**我的判分键错了**：K2 第一版要求"计划里仍必须有 `cut(crate::button::NODE_ID)`"——那是**指定机制**，
把第三轮对照臂那种同样合法的机制判成失败（**假负**）✗✗。改成：**K2 只判负面**（计划不再指向项目外的
crate），**正面（面是否还在）完全交给 K7**（读构建脚本 OUT_DIR 的 `generated_lib.rs` + `source_scope.tsv`
——权威产物）。改后**两臂各 8/8** ✓。⇒ 这与我刚立的"判据不许写机制、正面要读权威产物"是同一条，
**我先写错了、又被自己的实验抓出来**。
