# 针对"复杂原因 bug"的优化分析（第七轮证据 + 维护者点名的四类问题）

## 0. 总诊断

我们不是答案不准（1 真赢/21 平手/0 输），而是**每问一次只答一半 ⇒ 逼出下一跳**：仪器调用 113 : 84、
步数 304 : 273、仪器回复 166.7k : 149.7k 字符。⇒ **KPI 换成"每题仪器调用数/步数"**，token 次之，
质量红线（根因命中 / 构造反证 / 最小性 / 附带损伤 / 判据信息不丢）不动。

## 1. 四类问题逐类分析（维护者点名）

每类给：**为什么 AI 会错 → 我们架构结构上有什么 → 今天缺什么 → 优化方向 → 怎么机械验证 → 证伪条件**。

### A. 供应链驳杂（同族对象约定不一致）
*例：`button` 用相对坐标而逻辑按世界坐标写 ⇒ 字体/阴影偏移；`slider`/`timeline` 用世界坐标且正确。*

- **为什么 AI 会错**：单文件内部自洽、局部"看起来对"，错**只在同族之间**。AI 逐文件读时天然看不到
  "同族集合"这个上下文。
- **我们结构上有什么**（别人没有的）：**注册树给出的同族集合**（同一 parent 下的对象）+ 每个对象的
  声明字段（`exports`/`handle_traits`/`parts`/槽位）+ 逐函数 `direct_calls`（可推"它用了哪一族 API"）
  + doc 首行。
- **今天缺什么**：所有工具都是**单节点视角**（`callgraph`/`search`/`read`/`uses`），总账是**全树聚合**；
  **没有"同族 × 某个属性"的并列视图**，所以"谁离群"要靠 agent 自己逐个读文件比对（第七轮 `fa`/`fb`
  就是这么做的：7 次与 6 次调用）。
- **优化方向**：新增**一致性视图**——给定 parent（或某个信号：API 前缀、字段、槽位、导出名），
  一次列出 `同族对象 × 该属性`，并**只点名少数派**（`outliers: 1 of 3`）。信号必须**可判定且与用例无关**
  （不写死文件名/数值）：例"调用了 `*_world` 族 vs `*_local` 族"、"声明的 `parts` 名"、"导出的渲染契约名"。
- **机械验证**：在三兄弟里注入约定漂移（一个改用另一族 API 并把算式改成"内部自洽但语义错"），
  真值 = 哪个对象哪几行；判分看**一次调用**是否点名离群者。
- **证伪条件**：只有 3 个兄弟时，agent `ls` + 逐个 `read` 也能发现 ⇒ 那时我们的优势是**成本**不是**可能**；
  把兄弟数做到 8–30 个，才可能变成"几乎不可手工穷举"。**规模要写进题面**。

### B. 采信未落实（设计过、没继续执行；且要容忍架构演化）
- **为什么 AI 会错**：架构约束不在**任何一个文件**里——它在"某个标本 + 后来新增对象应当照做"这条
  **约定**里；AI 没有"约定"的载体，只能靠人提醒。
- **我们结构上有什么**：**采信台账**（anchor / certifies / files / fingerprint / verifier / why）+
  标本对象的声明形状 + "租约"语义（漂移只置 needs-confirmation，续期是显式追加）。
- **今天缺什么**：`adopted` 只报每条 verdict（provisional/lapsed），**不比对"新对象是否具备标本那条性质"**；
  也没有"**声明了但没落实**"的视图（如：面声明了 `parts` 却没有 `PartsContract` 实现、声明了
  `handle_traits` 却没实现、doc 承诺了某个不变量而没有任何门禁/测试在读）。
- **优化方向**：① **标本一致性比对**：把标本的**可推导形状**（声明字段/零件/句柄/导出/调用族）抽成
  "约定指纹"，对同族逐个比对，报"哪些对象缺哪一条"；② **演化容忍**：比对基准取**台账当前生效条目**
  （而不是冻结快照）⇒ 约定本身变了，续期那一次就是记录变更的事件 ✓；③ **"设计未落实"栏**：把
  "文档/台账声明 但无实现/无门禁/无测试覆盖"的项列出来，并自报边界（不判语义正确性，只判"有没有"）。
- **机械验证**：先采信标本（真台账，`provisional`），再加两个同族对象——一个照做、一个**只缺一条声明**；
  真值 = 缺哪条、在哪个对象；判分看是否**一次**给出"1 of 3 缺 parts 声明"。
- **证伪条件**：agent `cat .nichlink/adopted/entries` 能读到标本摘要 ⇒ 若它能手工把摘要与三个对象
  逐个对齐，则无绝对优势；差异只可能在**声明形状的推导**（要从源码/树里取，而不是读台账）上。

### C. 跨文件因果链（症状与因跨文件、跨层）
- **为什么 AI 会错**：症状在 Z（渲染错），因在**三跳之外**且在**计划/作用域**层（例：入口没声明切口
  ⇒ 新面被构建期作用域剪掉；或槽位 `full=false`）。
- **我们结构上有什么**：跨成员调用图 + `source_scope.tsv` + `graft_plan.tsv` + 槽位计数 + 身份
  （NodeId 随 `file!()` 变化）。
- **今天缺什么**：这些事实分散在 4–5 个工具里 ⇒ 每个跳一次（第七轮 `r1` 8 次、`s3` 13 次）。
- **优化方向**：**因果链视图**——给定症状点，一次返回"上游决定性事实"：① 谁调用它（含跨成员与是否测试）；
  ② 它所在面是否进发布树（计划/作用域）；③ 接线（切口/`full`）；④ 是否被特性门控；⑤ 契约来源行。
  每一条都带"这一条不覆盖什么"。
- **机械验证**：注入"入口没声明切口"这类因，症状设成运行期"面不见了"；真值 = 缺哪条声明；
  判分看**调用数**（理想 2–3 次）与是否点名计划层事实。
- **证伪条件**：agent `cat target/nichlink/out/*.tsv` 能拿到同样事实 ⇒ 我们只在**推导与定位**（哪一行、
  哪条槽位）上领先；要设计成"tsv 里没有直接答案，必须与树/源码联立"。

### D. 单文件多算法逻辑（一个文件里三套算法，错在一支）
- **为什么 AI 会错**：整段代码"看起来像样"，读一遍很难定位**哪一支**错；且测试可能只覆盖另外两支。
- **我们结构上有什么**：分支级栏（构造上不可达的臂）+ 契约 vs 实现 + 函数级覆盖映射 + doc 首行。
- **今天缺什么**：没有"**文件级摘要**"（这个文件有几套算法、各自的分支、哪些分支有测试、哪些臂死、
  契约行在哪）⇒ agent 只能 `read` 整文件再自己数。
- **优化方向**：`digest <file|node>`：算法/分支清单 + 每支覆盖情况 + 死臂 + 契约行 + 关键调用者，
  **默认短档**（≤20 行）、整表走显式开关。
- **机械验证**：一个文件三套算法、其中一套的一支写反（默认面绿、恰好一支没测到）；真值 = 哪支哪行；
  判分看调用数与是否点名"这支没有测试 + 与契约不符"。
- **证伪条件**：codegraph 的 `node` 一条就给整函数源码，读一遍也可能看出 ⇒ 我们只在"**覆盖 + 死臂 +
  契约**一次打包"上领先，属**成本/包装**优势。

### E. 多层交叉检索（debug 的层级跳跃）+ token
- 现实：症状→函数→调用者→跨成员消费者→计划/作用域→声明/契约→台账，**每层一次调用**。
- 优化方向：**每次答案预支下一层**（`next <tool> {keys}`），并把"必然要问的下一跳"直接放进答案
  （第七轮实测 `--list` 两轮 0 次调用 ⇒ 不能指望 agent 主动查形状）。
- 机械验证：同一批题跑改前/改后，比**调用数与步数**，并要求**判据信息一条不丢**（期望文件 + 机械判据）。

## 2. 能力缺口清单（按"别人做不到"的程度排序）

| 缺口 | 谁能做 | 现状 | 备注 |
| --- | --- | --- | --- |
| **同族 × 属性 一致性视图（A）** | 只有我们（需要"同族集合"） | 无 | 规模大时几乎不可手工穷举 |
| **标本一致性 + 设计未落实（B）** | 只有我们（需要台账语义） | 只有逐条 verdict | 需容忍演化（基准取当前生效条目） |
| **因果链一次跨层（C）** | 我们（计划/作用域）+ 部分通用 | 分散在 4–5 工具 | 与 `affected` 有重叠，需明确边界 |
| **文件级摘要（D）** | 通用（我们只是打包更好） | 无 | 只能算成本优势 |
| **每题调用数/步数（E）** | 双方都能做 | 我们更高 | 这是本轮最该打的指标 |

## 3. 执行顺序（先做便宜且零风险的）

1. **D2 形状进必经路径**（白跑 5→0；改两处文案 + `--json` 位置 + 钉子）
2. **E 预支下一跳**（答案尾注 `next`；`callgraph` 直说"调用者在另一个成员"）
3. **D3 默认短档扩到家族/范围题**（`fd/fe/h1` 13k → ≤9k；计数与边界永不抽掉）
4. **C 因果链视图**（一次给上游决定性事实）
5. **A 一致性视图** 与 **B 标本/未落实视图**（真正"别人做不到"的两项，需要新的声明/推导设计）
6. **D 文件级摘要**

## 4. 验证方式（测试与交叉验证阶段才用 team）

- 验证优化**不需要对照臂**：改前/改后两个二进制在同一批树上跑，比调用数/步数/字符 + 判据信息不丢；
- 复杂 bug 用"注入 + 构造真值 + 机械判分"，题面**不含答案**，参照与答案键放 `.audit/`；
- 独立复核：member 自建二进制、不引实现者报告、含反证（删预支行/去掉新栏 ⇒ 对应钉子必须变红）。
