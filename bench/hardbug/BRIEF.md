# 实战批次题面（复杂原因的 bug）——设计种子

判据 KPI（从"字节"改成）：**每题仪器调用数 / 步数** + token（原始与 carried）+ **是否构造了反证** +
根因命中（file:line + 机制）+ 修复最小性 + 附带损伤。**证伪条件先写**：若配 codegraph 的称职 agent
靠读 `target/nichlink/out/*.tsv` 与手工推导也能拿下，则判"我们无绝对优势"，只报"少调用/少往返"。

## 四类题（每类都要：注入配方 + 构造真值 + 机械判分 + 理想路径 + 必须拒绝的捷径）

**H1 供应链驳杂**：同族对象里，一个用了另一种约定（例：`button` 用相对坐标、`slider`/`timeline` 用世界
坐标），于是**局部都合理、错在彼此不一致**；症状表现为字体/阴影偏移这类"看起来像渲染 bug"的东西。
决定性事实：注册树能给出**同族集合**与每个对象的约定（声明字段或可推导），我们应当**一次调用**列出
"同族对象 × 各自约定 + 离群者"；对照组没有"同族"这个概念。

**H2 采信未落实**：架构/采信过的约束（specimen）在后来新增的对象上**没有执行下去**；且必须容忍开发中
的架构演化（不能拿冻结的 oracle 当真理）。决定性事实：采信台账（anchor/files/fingerprint/verdict）+
逐对象比对"是否具备被采信的那条性质"。要点：**报"设计过但没落实"**，而不是报"测试挂了"。

**H3 跨文件因果链**：症状在 Z 文件，因在**计划/注册面三跳之外**（例：入口没声明切口 ⇒ 构建期作用域把
新面剪掉；或槽位 `full=false`）。决定性事实：`source_scope.tsv` + `graft_plan.tsv` + 插槽计数。

**H4 单文件多算法**：一个文件里三套算法逻辑，错在其中一支的一个分支上（不是整段错）。决定性事实：
分支级栏（构造上不可达的臂）+ 契约 vs 实现 + 覆盖映射。

## 每次出题必须自证（否则不是题、是故事）

1. 注入处**真红**（命令 + 原始输出 + 退出码），文档化修法**真绿**；
2. 真值**由构造给出**（不是人写答案），且**机械可判**（判分脚本，不允许模型当裁判）；
3. 每题的**理想路径**（几步、哪几个工具）与**必须拒绝的捷径**写死；
4. 两臂在**同一棵注入副本**上跑；题面不含答案；`pristine-*` 参照与答案键放 `.audit/`。

## 与"链"和"钱"的关系（本轮要回答的问题）

- 我们的答案必须**预支下一步**：形状、同族集合、边界、下一跳，全放进**每次答案**里（`--list` 两轮
  0 次调用，不能指望它）；
- 目标：**更少调用/更少步数** + **更小 token** + **根因命中不降**；任何一题若我们的调用数 ≥ 对照组，
  要在报告里给出归因（是工具缺口还是路径设计）。
