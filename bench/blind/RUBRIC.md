# 盲评评分表（维护者给 kimi 的标准）

原话：「你要对比各个任务的 **token 消耗：输入/未命中/命中/输出**。以及**答案的优质程度**，**补丁感是不是太强**等，
新建项目时是不是更省 token、**结构是不是更好**、**算法是不是更不绕更像人写的代码**等等。」
「…结构上惰性很大，修复 bug 和**糊纸一样一层一层的**…**补丁感可以使用多轮 bug 修复进行测试**。」

请对 `blind/<题>/A.md` 与 `B.md` 打分（1–5，5 最好），每项给一句证据（引用答案里的原句/代码/命令）：

| 轴 | 问什么 | 1 分长什么样 | 5 分长什么样 |
| --- | --- | --- | --- |
| 1 正确与完整 | 结论对不对、证据够不够、四条要求都答了吗 | 结论含糊或缺要求 | 结论准确、每条都有命令与输出 |
| 2 补丁感 | 改动是不是"一层层糊上去"的；有没有顺手改无关处 | 面面俱到地堆、或碰了不该碰的 | 只改必要的那处，并说明为什么别处不动 |
| 3 结构 | 新东西放在该在的层次里吗；骨架是否清晰 | 塞进现有函数、结构混乱 | 层次清楚、名字与位置都对 |
| 4 算法/写法像不像人写 | 是不是绕、是不是生硬的套话式代码 | 绕、重复、像补丁 | 直、短、像人写的 |
| 5 工作流价值 | 对"AI 做项目"这件事帮助大吗（少走弯路、可判定的停止条件、可复核的证据） | 靠猜、无停止条件 | 一步到位的入口、明确的判据、可复核 |

输出格式（每题一段）：
```
## <题>
A: 1=… 2=… 3=… 4=… 5=… · 一句总评
B: 1=… 2=… 3=… 4=… 5=… · 一句总评
胜者：A / B / 平（给理由）
```
**纪律**：不许读 `bench/keys.md`、`runs/`、`briefs/`、任何 `score-*.py`，也不许去 `/tmp/scen-runs` 里
比对——你只许读 `blind/` 目录。你不需要、也不该猜哪一份是谁的。
