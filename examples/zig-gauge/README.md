# Zig-declared face example / Zig 声明面示例

A host whose registration tree contains a face declared **in Zig** (`gauge/native/gauge/gauge.zig`),
inside a subtree that is partitioned into its own crate. It answers three questions as code:
在 Zig 里声明面的宿主，且该面所在的子树被分区成独立 crate。它用代码回答三个问题：

1. can a face be declared in Zig and be compiled into the same tree the Rust half is baked into?
   （Zig 面能否被编译进与 Rust 那一半相同的树？）
2. can a Zig face hang under a Rust face, and a Rust face under the Zig one?
   （Zig 面能否挂在 Rust 面下、Rust 面又挂在 Zig 面下？）
3. does the partition move the Zig source with the subtree — the fragment compiles it, the host does
   not? （分区会不会把 Zig 源码随子树搬走——碎片编译它、宿主不编译？）

```sh
# Zig 必须可用：本检出经 `nix shell nixpkgs#zig -c` 取得（或给 `XIRANG_ZIG`）。
# Zig must be available: this checkout gets it via `nix shell nixpkgs#zig -c` (or set XIRANG_ZIG).
cd examples/zig-gauge && cargo test --offline
```

- `gauge/` — the host: `Shop` stays; `add_crates.rs` declares the `shop::panel` subtree as crate
  `panel`.
- `crates/gauge-panel/` — generated by `xirang crates --write`; its build compiles the Zig face
  because the face's parent lives in this fragment.
- `verify/tests/tree.rs` — the two crates assemble one tree, with the Zig face present once.
- `gauge/tests/tree.rs` — the host keeps only `Shop`.
